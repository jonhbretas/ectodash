<objective>
**Phase goal (per ROADMAP.md):** Users can create, edit, and track the status of demandas (tasks), with overdue items flagged automatically without manual marking.

This plan builds the phase's entire data foundation: the `demandas` table, the `demanda_responsaveis` many-to-many link table (the user's locked decision overriding RESEARCH.md's single-FK assumption), permissive-but-authenticated RLS matching Phase 2's SELECT-gates-UPDATE lesson, and the `demandas_com_status` view that derives "atrasada" fresh on every read — never a stored, cron-flipped column, which Postgres cannot even create for this shape (`now()`/`current_date` are STABLE, not IMMUTABLE).

No UI ships in this plan. It is Wave 1 specifically so the schema and its RLS contract are proven live, against the real hosted project, before any Server Action or form is written against it — mirroring how Phase 2 proved `has_role()` before any dependent policy was built.

Purpose: get the two hardest-to-reverse decisions right first — the multi-responsável join shape and the read-time overdue derivation — with a live test proving both directions of every access boundary, so Wave 2's tracer builds UI against a foundation already known to be correct.
Output: `supabase/migrations/0003_demandas.sql` applied to the live hosted project, and `tests/db/demandas-rls.test.ts` proving DEM-01/DEM-02/DEM-03's data-layer contract end-to-end.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Signed-in (`authenticated`) client -> `public.demandas` / `public.demanda_responsaveis` | Any authenticated volunteer can issue arbitrary writes against the auto-generated Data API this phase; RLS is the only gate |
| Client-submitted `criado_por` -> `public.demandas` INSERT | A client legitimately says which demanda to create, but must not be able to say who authored it |
| `public.demandas_com_status` view -> underlying RLS on `public.demandas` | A view defined with the wrong owner-privilege mode can silently leak every row regardless of the table's own policies |
| Developer machine -> hosted Postgres | `db push` applies arbitrary DDL with owner privileges to the live institutional database |
