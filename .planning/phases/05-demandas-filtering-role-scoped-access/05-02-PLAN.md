<objective>
**Phase goal (per ROADMAP.md):** Users can filter/group demandas and only see/edit what their role permits, through short, accessible forms.

This plan is Wave 2 — it builds DEM-04's filter/group UI and UX-02's conclude-confirmation step entirely on top of plan 05-01's already-proven, already-live RLS narrowing. It adds one new filter bar (área/projeto Select, responsável Select, Agrupar por Select — capped at 3 controls per 05-UI-SPEC.md), a distinct filtered-to-zero-results empty state, a server-rendered role-scoped-view notice that correctly names one or several áreas for a líder (per plan 05-01's multi-área schema), and a `window.confirm()` gate on the existing "Marcar como concluída" action. No schema or RLS change happens in this plan — every filter/group/notice value is read from data RLS has already scoped, and every write still flows through the same Server Actions plan 05-01 already secured.

Purpose: deliver the phase's user-visible capability (find relevant demandas quickly, see confirmation that your view is correctly scoped, get a clear confirm step before an important action) without touching the trust boundary again — this wave is deliberately UI-only so it can be reviewed and iterated on independently of the higher-risk RLS work.
Output: the demandas list at `/` supports área/projeto and responsável filtering plus grouping, shows a role-appropriate scoped-view notice, presents a distinct empty state when a filter matches nothing, and requires confirmation before concluding a demanda.
</objective>
