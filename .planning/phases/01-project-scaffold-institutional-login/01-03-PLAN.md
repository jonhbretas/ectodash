<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser -> login Server Action | Untrusted e-mail input crosses here; the response is observable by anyone |
| E-mail inbox -> /auth/callback | An untrusted `code` query parameter crosses here and is exchanged for a session |
| Unauthenticated request -> protected routes | Middleware is the only enforcement point; the UI is not a boundary |
| Developer machine -> Supabase Auth Admin API | The service-role key bypasses every RLS policy |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-11 | Spoofing | `requestMagicLink` Server Action auto-creating accounts | high | mitigate | `shouldCreateUser` pinned to false on the single sign-in call (D-02) plus the Dashboard sign-up toggle OFF as defence in depth; asserted by unit test 1, live integration test 5, and human step 5 |
| T-01-12 | Tampering | Open redirect via a caller-supplied `emailRedirectTo` / `redirectTo` | high | mitigate | redirect built only from server-side `NEXT_PUBLIC_SITE_URL`; grep asserts the option is never derived from formData/searchParams/headers; unit test 2 asserts an injected field is ignored |
| T-01-13 | Spoofing | Unauthenticated access to the dashboard route | high | mitigate | middleware validates with `getUser()` and redirects to /login before any page renders; asserted by the unauthenticated curl criterion |
| T-01-14 | Elevation of Privilege | Service-role key reachable over HTTP through the seed script | high | mitigate | script lives outside `src/`, is never imported by application code, and is invoked only locally; grep asserts no reference from the module graph |
| T-01-15 | Information Disclosure | Institutional e-mail enumeration through the login form | medium | mitigate | identical state object, identical copy, and an unbranched control flow on every outcome; unit test 3 asserts equality across the error and non-error paths |
