<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Browser cookie jar -> Next.js middleware | The session cookie is the sole bearer of identity on every request |
| Vercel environment configuration -> deployed runtime | Anything set here is available to deployed code; public-prefixed values also reach the browser |
| Public internet -> production deployment | The deployed origin is reachable by anyone, unlike localhost |
| Supabase Auth URL allow-list -> e-mail link targets | The allow-list is what stops a link from being redirected to an attacker-chosen origin |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-19 | Spoofing | Stale or unvalidated session accepted server-side | high | mitigate | every server-side check uses the user-fetching auth call, which validates against the Auth server and exercises the refresh token; grep-enforced and asserted by tests 1-2 |
| T-01-20 | Tampering | Auth e-mail links redirected to a non-allow-listed origin | high | mitigate | Supabase Auth URL Configuration restricted to the production Vercel origin plus localhost; human step 3 verifies the actual rendered link target |
| T-01-21 | Elevation of Privilege | Service-role key present in the Vercel production environment | high | mitigate | the key is deliberately not added; `vercel env ls production` absence is an acceptance criterion; the only consumer is the local-only seed script |
| T-01-22 | Information Disclosure | Session cookie theft via MITM or XSS | medium | mitigate | `@supabase/ssr` httpOnly/secure/sameSite defaults left untouched; Vercel serves HTTPS by default, verified by the HTTPS acceptance criterion |
| T-01-23 | Denial of Service | A shortened cookie lifetime or an added timeout silently logging volunteers out | medium | mitigate | test 3 asserts a minimum 180-day cookie lifetime and grep asserts no lifetime override or timeout identifier exists in application code (D-03) |
| T-01-24 | Repudiation | No application-level authentication audit trail | low | accept | Supabase Auth's built-in log covers sign-in events at this institution's scale; a first-party audit log is not warranted for v1 |
| T-01-25 | Denial of Service | Free-tier Supabase project auto-pausing after 7 idle days, breaking production login with no application error | medium | accept | Deferred with a tracked follow-up to Phase 7, where the first Vercel Cron job ships and can carry the keep-alive write (RESEARCH.md Open Question 1). Recorded in STATE.md blockers at phase close |
</threat_model>
