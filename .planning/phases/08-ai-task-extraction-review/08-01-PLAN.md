<objective>
**Phase goal (per ROADMAP.md):** Users paste a meeting summary already generated by an external tool (Fireflies/tl;dv), and new demandas are proposed from it by AI — but only created after a human confirms them, never automatically.

This plan is Wave 1 — the phase's server-side extraction foundation and the one required package-legitimacy checkpoint, both proven before any paste/review UI is written (Wave 2). It does four things, in this order: (1) presents the `@google/genai` package-legitimacy override for human confirmation, then installs it — mandatory per the Package Legitimacy Gate protocol even though 08-RESEARCH.md's own research already resolved the `[SUS]` "too-new" false-positive flag with direct npm registry evidence (official `googleapis` GitHub org, package registered March 2025, 17.9M weekly downloads); (2) builds `matchResponsavel()`, the pure, deterministic email-local-part substring matcher that resolves an AI-extracted name string to a real `profiles.id` or `null` — never a guessed UUID; (3) builds `extractionResponseSchema`, the Zod schema that re-validates Gemini's own JSON output as untrusted external data, distinct from `demandaSchema`; (4) builds `extractDemandas`, the Server Action that calls `@google/genai`'s `generateContent()` with `responseSchema` enforcement against the pasted text, re-validates the response, matches each suggestion's responsável, and returns a plain `suggestions[]` array to the caller — with **zero database writes**, proven by a dedicated integration test that this Server Action structurally cannot create a demanda under any input.

This is deliberately separated from Wave 2's review UI: gating a package install behind a human confirmation, and getting the extraction/matching/validation logic and its no-write invariant proven correct in isolation, are both higher-risk, harder-to-reverse-if-wrong changes than composing already-proven server logic into client-facing screens — the same "proven primitives first, feature UI second" sequencing Phase 7 (07-01 before 07-02) already established for this project.

Purpose: get the Gemini call, the responsável-matching heuristic, the AI-output validation, and the package-legitimacy confirmation right and structurally proven — especially IA-04's "never created without review" invariant — before any review-screen code is written on top of them.
