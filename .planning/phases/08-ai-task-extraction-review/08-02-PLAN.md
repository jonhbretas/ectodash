<objective>
**Phase goal (per ROADMAP.md):** Users paste a meeting summary already generated by an external tool (Fireflies/tl;dv), and new demandas are proposed from it by AI — but only created after a human confirms them, never automatically.

This plan is Wave 2 — the phase's paste/review UI, built entirely on top of Wave 1's already-proven `extractDemandas` Server Action and `matchResponsavel` heuristic. It does three things: (1) `page.tsx` at the new `/demandas/extrair` route, a Server Component role-gating `coordenador_geral`/`lider_area` (per the user's confirmed decision) with the exact non-redirecting, calm access-denied state `/painel` already established; (2) `import-form.tsx`, Screen 1's paste textarea + `Processar` button, following `login-form.tsx`'s `SubmitButton`/`useFormStatus` pending-state pattern exactly, transitioning in place to Screen 2 once `extractDemandas` returns suggestions; (3) `suggestion-review-list.tsx`, Screen 2's per-card review UI — each card independently editable, each with its own Confirmar (calling the unmodified `createDemanda` with the card's current field values) and Rejeitar (pure client-state removal, zero network calls) — plus the header entry-point link on `/` visible to the two eligible roles.

This wave is deliberately sequenced after Wave 1: composing UI on top of an already-integration-tested, zero-write-proven Server Action is lower-risk than building the UI and the extraction logic simultaneously, and lets this plan focus entirely on faithfully implementing 08-UI-SPEC.md's locked screens/copy/access contract without also having to re-verify IA-04's invariant from scratch — that verification already happened in Wave 1 and this plan's job is simply to never violate it (no new insert path, ever).

Purpose: give the coordenador/líder a working paste-and-review flow that makes IA-01 (paste), IA-03 (see suggested título/responsável/prazo), and IA-04 (edit/reject before creation, no auto-create) all observably true end-to-end.
Output: `/demandas/extrair` live with the full paste -> processing -> review -> per-card confirm/reject flow, wired to the unchanged `createDemanda` action; the entry-point link visible to coordenador_geral and lider_area on `/`.
</objective>
