<objective>
**Phase goal (per ROADMAP.md):** Coordenador can view, in a single dashboard, the real status of every demanda, project, and volunteer across the institution.

This plan is the phase's tracer — the entire coordinator dashboard, end-to-end, in one wave. Unlike Phase 5, this phase introduces **zero new database migrations**: 06-RESEARCH.md verified directly from `0004_demandas_role_scope.sql`'s actual SELECT policy text that a `coordenador_geral`'s ordinary, already-live RLS grant already returns every institution-wide demanda with no further condition. This plan is therefore a pure, additive UI/aggregation layer: one new route (`/painel`), one new shadcn component (`card`), and three small presentational components composing already-existing display primitives (`DemandaTable`, `DemandaCard`, `StatusBadge`, `OverdueBadge`).

**Route name decision (resolving the 06-RESEARCH.md vs 06-UI-SPEC.md conflict):** 06-RESEARCH.md recommends `/coordenador`; 06-UI-SPEC.md — the later, more specific, locked design contract — specifies `/painel`. This plan adopts `/painel`. 06-UI-SPEC.md's reasoning holds: `/coordenador` risks reading as a second, competing name for the `(dashboard)` route group's own internal "dashboard" concept, whereas `/painel` is the exact PT-BR term this page's own locked heading copy already uses ("Painel do coordenador"), consistent with every other route already being a plain Portuguese noun (`/demandas`, `/login`). RESEARCH.md's *technical* reasoning (Server Component role read + redirect-or-render, no proxy.ts change, no new migration) is fully preserved — only the URL segment and the non-coordenador handling (see below) differ from its specific proposal.

**Access-denied-state decision (resolving the same two documents' UX disagreement):** 06-RESEARCH.md's Pattern 3 proposes `redirect("/")` for a non-coordenador visitor; 06-UI-SPEC.md's Route & Access Contract explicitly overrides this with a same-URL, calm "este painel é exclusivo do coordenador" render, reasoning that a silent bounce is worse UX for this project's elderly-inclusive audience who may have clicked a shared link or bookmark. This plan follows 06-UI-SPEC.md's locked contract — no `redirect()` call for a role mismatch. Both documents agree this check is UX polish only, never the authorization boundary; RLS remains authoritative regardless of which UX treatment renders.

Purpose: deliver COORD-01/02/03's entire user-visible capability — one dashboard, overdue highlighted, área/voluntário counts — as a single reviewable, end-to-end vertical slice, since nothing in this phase is high-risk enough (no RLS change) to warrant splitting data-layer work from UI work into separate waves the way Phase 5 did.
Output: `/painel` — a coordenador-only dashboard with 5 stat cards (total, atrasadas, pendentes, em andamento, concluídas), a breakdown-by-área section, a breakdown-by-voluntário section, and an institution-wide overdue panel, plus the empty-institution and non-coordenador access states.
</objective>
