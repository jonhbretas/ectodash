**Phase goal (per ROADMAP.md):** Volunteers and leaders are automatically reminded by email about approaching and overdue demandas, with reliable, traceable delivery.

This plan is Wave 1 — the phase's data-layer foundation and the one required package-legitimacy checkpoint, both proven/confirmed before any cron route or email-sending code is written (plan 07-02, Wave 2). It does three things: (1) ships `supabase/migrations/0005_reminder_logs.sql`, creating `demanda_reminders_log` (the atomic per-reminder dedup table, LEMB-03) and `reminder_runs` (the per-run success/failure/count summary, LEMB-04) as two separate, RLS-enabled, coordenador-only-readable tables; (2) presents the `resend`/`react-email` package-legitimacy override for human confirmation, then installs both packages — this checkpoint is mandatory per the Package Legitimacy Gate protocol even though 07-RESEARCH.md's own research already resolved the `[SUS]` flag with direct npm registry evidence (package registration dates 2016/2017, 8-10 years of continuous maintenance by the same GitHub org, tens of millions of weekly downloads); (3) implements `reminderTipoFor()`, the pure eligibility function classifying a demanda as `'atrasada'`, `'aproximando'`, or ineligible (`null`), proven with unit tests covering the 3-day window's boundary cases.

Purpose: get the dedup constraint, the run-log schema, and the package-legitimacy confirmation right and proven before any email-sending code is written on top of them.
Output: `supabase/migrations/0005_reminder_logs.sql` applied to the live hosted project; `resend`/`react-email` installed in `package.json` only after human confirmation of the legitimacy override; `src/lib/reminders/eligibility.ts` with passing unit tests; `.env.local.example` extended with the two new env var names this phase introduces.
