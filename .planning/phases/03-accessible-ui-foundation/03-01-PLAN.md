<objective>
**Phase goal (per ROADMAP.md):** The application's base interface is legible, touch-friendly, and responsive enough for an elderly-inclusive volunteer audience to use without friction (UX-01, UX-03).

This plan executes the single highest-risk, foundational step of the phase: initializing shadcn/ui, reconciling its generated `globals.css` theme block against this project's already-locked hex palette (RESEARCH.md's Pitfall 1/2, "the single highest-risk step in the shadcn adoption" per 03-UI-SPEC.md), editing the copied `Button`/`Input` source so their default size meets this project's `min-h-14`/`text-xl` floor once (not per call site), and adding the one genuinely new accessibility artifact this phase requires: a skip-to-content link.

This plan deliberately does **not** touch any already-shipped, already-tested surface (login, dashboard, demanda forms/list) — it only scaffolds the tools Plans 03-02 and 03-03 will consume. Isolating this step lets the CSS-reconciliation risk be proven and verified (build succeeds, existing suite green, no visual regression on the one page touched — `layout.tsx`) before any retrofit begins.

Purpose: land shadcn/ui and the formalized design-token layer without regressing anything, so the retrofit plans that follow have safe, correctly-sized primitives to consume.
Output: `components.json`, `src/lib/utils.ts`, 6 shadcn component source files (2 of them edited for the accessibility floor), a reconciled `globals.css`, and a working skip-link in `layout.tsx`.
</objective>
