<objective>
**Phase goal (per ROADMAP.md):** The application's base interface is legible, touch-friendly, and responsive enough for an elderly-inclusive volunteer audience to use without friction (UX-01, UX-03).

This plan retrofits the demanda create/edit form and the demandas desktop table/badges onto shadcn's `Input`/`Label`/`Table`/`Badge` primitives scaffolded in Plan 03-01 — the second half of this phase's four-surface Retrofit Contract, running in the same wave as, and touching a fully disjoint file set from, Plan 03-02 (login/dashboard-shell). The native `<select multiple>` for `responsavelIds` deliberately stays untouched, matching `03-UI-SPEC.md`'s locked decision and `RESEARCH.md`'s independent confirmation that shadcn's `Select` cannot represent multi-value selection at all.

Every change here is gated on `03-UI-SPEC.md`'s "componentize losslessly, restyle minimally" rule, with `Badge`'s migration risk specifically de-risked by `RESEARCH.md`'s Pitfall 4 finding (shadcn's actual default is `rounded-full`, not `rounded-md` as `03-UI-SPEC.md` originally assumed) — meaning this migration can proceed with more confidence than the UI-SPEC's own cautious framing implied, while still preserving the explicit fallback to plain `<span>` if reconciliation proves awkward in practice.

Purpose: complete the phase's formalization work on the highest-visibility, already-tested surface (the demandas list/table/form a coordinator uses daily) without regressing any of Phase 4's locked visual contract.
Output: the demanda form and desktop table/badges render through shadcn primitives (or are explicitly left native per the fallback), with zero visible regression.
</objective>
