<objective>
**Phase goal (per ROADMAP.md):** The application's base interface is legible, touch-friendly, and responsive enough for an elderly-inclusive volunteer audience to use without friction (UX-01, UX-03).

This plan retrofits the login screen, the sign-out control, and the dashboard shell (the three `(dashboard)` group pages' shared wrapper) onto shadcn's `Button`/`Input` primitives scaffolded in Plan 03-01, and extracts the triplicated page-wrapper `className` string into a single `PageContainer` component — the concrete DRY win `03-UI-SPEC.md`'s Retrofit Contract calls for. It also completes the skip-link's jump target by adding `id="main-content"` to every `<main>` these three pages render.

Every change here is gated on `03-UI-SPEC.md`'s "componentize losslessly, restyle minimally" rule: the rendered DOM text, class list, computed size, and color must be indistinguishable from the pre-retrofit version. This plan runs in the same wave as, and touches a fully disjoint file set from, Plan 03-03 (which retrofits the demanda form and list/table/badges).

Purpose: prove shadcn's edited Button/Input can reproduce the exact existing pixel output on real, already-shipped, already-verified surfaces — and eliminate one genuine structural gap (the copy-pasted wrapper, the missing skip-link target) along the way.
Output: login, sign-out, and the three dashboard-group pages render through shadcn primitives and a shared PageContainer, with zero visible regression.
</objective>
